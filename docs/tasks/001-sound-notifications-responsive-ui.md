# Звуковые уведомления и адаптивный интерфейс desktop-клиента

Status: `Done`

Created: `2026-09-19`

Updated: `2026-09-19`

## Goal

Добавить в desktop-клиент управляемое звуковое уведомление о каждом новом коле,
который прошел пользовательские фильтры и появился в ленте, а также сделать
основной интерфейс и настройки удобными при ширине окна вплоть до установленного
минимума 250 px.

Пользователь должен иметь возможность быстро отключить звук из header, изменить
его громкость и выбрать собственный аудиофайл в настройках. Стандартным звуком
является
`src/client/static/audio/mixkit-positive-notification-951.wav`; аудиофайлы не
должны храниться в корне репозитория.

## Requirements

### Рабочая ветка и порядок реализации

- До начала реализации создать от актуальной целевой ветки отдельную ветку
  `feature/sound-notifications-responsive-ui` и выполнять все изменения этого ТЗ
  только в ней.
- Реализацию вести двумя вертикальными слайсами в указанном порядке. Каждый слайс
  должен включать необходимые типы, хранение состояния, сервисы, UI, тесты и
  документацию и завершаться работающим пользовательским сценарием.
- Не начинать второй слайс, пока проверки и критерии приемки первого не выполнены.

### Слайс 1. Стандартное уведомление и адаптивный header

- Добавить секцию `notifications` в пользовательские настройки со значениями:
  уведомления включены по умолчанию, громкость по умолчанию равна 70%, источник
  звука — стандартный файл.
- Воспроизводить звук один раз для каждого кола, который прошел фильтры и был
  добавлен в видимую ленту. Воспроизведение не должно зависеть от выбранного
  режима автооткрытия или успешности открытия ссылки.
- Не воспроизводить звук для отклоненных фильтрами сообщений, heartbeat,
  обновлений цены, повторного подключения и очистки списка.
- Использовать один канал воспроизведения: если следующий принятый кол поступил
  до завершения звука, остановить текущий звук и запустить его с начала. Ошибка
  загрузки или воспроизведения не должна препятствовать добавлению карточки,
  обновлению счетчиков или автооткрытию.
- В header непосредственно слева от кнопки настроек добавить квадратную кнопку с
  иконками `Volume2` и `VolumeX`. Нажатие мгновенно переключает уведомления,
  сохраняет настройку и не изменяет громкость или выбранный источник.
- Кнопка должна иметь понятные `title`, `aria-label`, `aria-pressed`, видимый
  focus и различимые включенное и выключенное состояния. Размер интерактивной
  области — не менее 36 x 36 px.
- В диалоге настроек добавить компактную панель Notifications с переключателем,
  ползунком громкости от 0 до 100% с числовым значением и кнопкой `Test sound`.
  Изменения применяются только после `Save`; `Cancel`, Escape и клик по backdrop
  оставляют активные настройки без изменений. Preview использует черновые
  значения.
- При ширине больше 360 px header остается в одну строку в порядке: состояние
  подключения, цена SOL, счетчик, свободное пространство, звук, настройки,
  очистка. При ширине 250–360 px он перестраивается в две устойчивые строки:
  показатели находятся сверху, а группа `звук → настройки → очистка` — снизу
  справа. Случайный перенос отдельных кнопок запрещен.

### Слайс 2. Пользовательский звук и полная адаптивность

- В панели Notifications добавить выбор локального файла `.wav`, `.mp3` или
  `.ogg` размером не более 5 MiB, отображение имени выбранного файла и действие
  `Use default`.
- До сохранения выбранный файл держать как черновик и разрешать его preview.
  Только после `Save` копировать файл в локальное хранилище приложения. `Cancel`
  не должен заменять действующий звук и не должен оставлять временные данные.
- Хранить не более одного пользовательского аудиофайла. Успешная замена удаляет
  предыдущий файл. Неподдерживаемый, слишком большой, пустой или
  невоспроизводимый файл показывает локальную ошибку и не меняет действующую
  настройку.
- Сохранять пользовательский Blob в IndexedDB через отдельный сервисный
  интерфейс. В существующем settings store хранить флаг включения, громкость,
  источник, идентификатор и безопасное отображаемое имя файла. UI и WebSocket
  store не должны напрямую обращаться к `Audio`, Blob или IndexedDB.
- Повысить версию экспортируемой схемы настроек до V5 и обеспечить импорт
  форматов V1–V4 с настройками уведомлений по умолчанию. JSON-экспорт содержит
  параметры и метаданные уведомлений, но не содержит бинарное аудио. Если после
  импорта ссылка на пользовательский файл недоступна на текущем устройстве,
  использовать стандартный звук и явно отобразить fallback в настройках.
- На ширине 250–359 px обеспечить responsive reflow всего аутентифицированного
  desktop-интерфейса: header, пустого состояния, ленты, карточек и диалога
  настроек. Не использовать глобальные `zoom` или `transform: scale`.
- На минимальной ширине не должно быть горизонтальной прокрутки, обрезанных
  кнопок или полей и элементов, выходящих за viewport. Длинные имена, тикеры и
  адреса должны переноситься либо сокращаться без расширения контейнера.
- Диалог настроек должен занимать доступную ширину; вкладки должны переходить в
  две колонки, составные поля — в одну колонку, а footer с действиями должен
  оставаться доступным без горизонтальной прокрутки.
- Существующая компоновка на стандартной ширине около 450 px не должна
  деградировать.

### Архитектура, данные и документация

- Определить тип `NotificationSettings` и добавить его в `SettingsSections`.
  Нормализация должна ограничивать громкость диапазоном 0–100, отбрасывать
  некорректные метаданные и гарантировать безопасные значения по умолчанию.
- Инкапсулировать загрузку, проверку, preview, сохранение и воспроизведение в
  audio notification service. Точка приема WebSocket-события должна вызывать
  этот сервис после успешной фильтрации отдельно от `AutoOpenDispatcher`.
- Не изменять серверный протокол и browser extension: функция полностью локальна
  для desktop-клиента.
- Обновить `docs/architecture.md` и `docs/project-status.md`, описав локальные
  настройки уведомлений, хранение пользовательского аудио и новое адаптивное
  поведение.

## Acceptance criteria

### Слайс 1

- Текущая ветка называется `feature/sound-notifications-responsive-ui`.
- При первом запуске принятый фильтрами кол отображается, запускает стандартный
  звук с громкостью 70% и продолжает делать это при выключенном автооткрытии.
- Отклоненное фильтрами событие и служебные WebSocket-сообщения звука не создают.
- Кнопка в header мгновенно отключает и повторно включает звук, сохраняет
  состояние после перезапуска и расположена непосредственно перед настройками.
- Изменение громкости и preview работают в черновике; `Save` сохраняет значение,
  а `Cancel` его отбрасывает.
- Header не переполняет viewport при ширине 450, 360, 320 и 250 px; на узких
  ширинах действия образуют отдельную аккуратную строку.
- Для измененного поведения добавлены unit- и component-тесты, а полный набор
  клиентских проверок завершен успешно.

### Слайс 2

- Валидный пользовательский звук можно выбрать, проверить, сохранить и
  воспроизвести после перезапуска приложения; `Use default` возвращает
  стандартный WAV.
- Отмена выбора, невалидный файл, превышение лимита и ошибка IndexedDB не ломают
  действующий звук и основной поток приложения.
- Экспорт не содержит бинарных данных. Импорт настроек с отсутствующим локальным
  custom-файлом использует стандартный звук без необработанной ошибки.
- При 250, 320, 360 и 450 px заполненная лента, карточки и все разделы настроек
  остаются читаемыми и управляемыми с клавиатуры без горизонтальной прокрутки.
- Импорт старых схем V1–V4, новый формат V5 и сервис пользовательского аудио
  покрыты regression-тестами.
- Документация обновлена, и полный набор клиентских проверок завершен успешно.

## Implementation notes

- Стандартный файл уже расположен по адресу
  `src/client/static/audio/mixkit-positive-notification-951.wav` и должен
  загружаться из frontend bundle по стабильному URL.
- При громкости 0% настройка остается включенной, но звук фактически бесшумен;
  быстрый переключатель управляет только флагом включения и сохраняет выбранный
  уровень громкости.
- Ошибки воспроизведения следует обрабатывать без блокирующих диалогов. Ошибки
  выбора файла показываются рядом с соответствующим контролом.
- После каждого слайса из `src/client` выполнить:

  ```powershell
  npm run format:check
  npm run lint
  npm run check
  npm run test
  npm run version:check
  npm run build
  ```

- Если реализация затронет Rust/Tauri, дополнительно выполнить из
  `src/client/src-tauri`:

  ```powershell
  cargo fmt --check
  cargo clippy --all-targets --all-features -- -D warnings
  cargo test
  cargo check
  ```

## Result

Реализованы оба слайса. Принятые фильтрами колы запускают управляемое звуковое
уведомление независимо от автооткрытия; доступны быстрый переключатель,
громкость, preview и стандартный WAV. Пользовательский WAV, MP3 или OGG
проверяется до сохранения и хранится единственной записью в IndexedDB, а схема
настроек V5 экспортирует только безопасные метаданные и импортирует V1–V4 со
значениями по умолчанию.

Header, лента, карточки и настройки адаптированы к ширине 250 px без
горизонтальной прокрутки и глобального масштабирования. Поведение настроек,
WebSocket pipeline, импорт старых схем и audio-сервис покрыты regression-тестами.
