# 0001. Независимое версионирование выпускаемых компонентов

- Статус: `accepted`
- Дата: `2026-09-19`
- Участники: maintainers

## Контекст

Desktop-клиент и браузерное расширение собираются отдельно и могут получать
изменения с разной скоростью. Сервер пока развертывается единым приложением, но
его внутренние модули со временем могут быть переписаны или выделены в
микросервисы. Общая версия репозитория связывала бы независимые выпуски, а
отдельная версия каждого внутреннего модуля создала бы процесс без отдельного
артефакта и жизненного цикла.

Ранее клиент дополнительно считал совместимым только расширение с той же
major-версией и использовал версию клиента для установки вложенного расширения.
Это не позволяло выпускать их независимо, хотя совместимость обмена уже
определяется bridge-протоколом.

## Решение

Каждый независимо выпускаемый компонент использует SemVer и component-specific
Git-тег:

- desktop-клиент — `client-vMAJOR.MINOR.PATCH`;
- расширение — `extension-vMAJOR.MINOR.PATCH`;
- текущий серверный deployment — `server-vMAJOR.MINOR.PATCH`.

Совместимость клиента и расширения определяется версией bridge-протокола, а не
совпадением версий продуктов. Сервер получает одну версию на deployable unit;
внутренние модули не версионируются отдельно. Новый серверный компонент получает
собственную версию только после появления независимых сборки и развертывания.
Версии внешних API и message schemas ведутся отдельно от версии server
deployment.

Операционные правила и источники версий перечислены в
[`versioning.md`](../versioning.md).

## Последствия

Клиент, расширение и сервер можно выпускать независимо, а по тегу однозначно
видно назначение артефакта. Вложенное расширение сохраняет свою версию. Изменение
протокола требует явного согласованного выпуска обеих сторон.

Появляется обязанность синхронизировать дублированные поля версии клиента и
вести release notes для каждой затронутой части. Выделение микросервиса потребует
добавить источник версии и release pipeline именно для этого сервиса.

## Альтернативы

- Одна версия всего репозитория отклонена: она создает фиктивные релизы
  неизменившихся компонентов и связывает независимые циклы поставки.
- Версия каждого серверного модуля отклонена: модули сейчас не являются
  отдельно потребляемыми или развертываемыми артефактами.
- Совместимость по major-версиям клиента и расширения отклонена: product version
  не описывает wire contract и мешает независимому развитию.
