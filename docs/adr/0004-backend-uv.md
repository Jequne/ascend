# 0004. Управление зависимостями backend через uv

- Статус: `accepted`
- Дата: `2026-09-27`
- Участники: команда Ascend

## Контекст

Backend устанавливал зависимости из двух requirements-файлов через pip.
Настройки инструментов уже находились в `pyproject.toml`, но локальный
`uv.lock` не содержал зависимостей и не использовался при установке.
Нужен единый процесс для разработки, проверок и Docker.

## Решение

Зависимости приложения объявлены в `src/server/pyproject.toml`, инструменты
проверок — в группе `dev`. Объявлены только используемые прямые зависимости;
транзитивные зависимости управляются через lock-файл. Версии оставшихся
прямых зависимостей сохранены. Requirements-файлы удалены.

Для Uvicorn сохранён набор `standard`, включая HTTP/WebSocket backend и reload;
для SQLAlchemy подключён набор `asyncio`, для PostgreSQL — `psycopg[binary]`.

`uv.lock` фиксирует полный граф, включая транзитивные и платформенные
зависимости, и хранится в Git. Изменения зависимостей и lock-файла проверяются
и коммитятся вместе. Установка выполняется через `uv sync --locked`, команды
разработки и проверки — через `uv run --locked`.

`.python-version` выбирает Python 3.14, как в Docker. Проект использует Python
3.14 (`>=3.14,<3.15`) и запускается из исходников (`tool.uv.package = false`);
`src/server/VERSION` остаётся источником версии серверного выпуска.

Docker копирует uv из официального образа с закреплённой версией и выполняет
`uv sync --locked --no-dev` до копирования исходников. `/app/.venv/bin` включён
в `PATH`; запуск приложения и Alembic не требует синхронизации или сети.

## Последствия

Один lock-файл используется локально и в Docker. `--locked` обнаруживает
рассогласование деклараций и lock-файла. Группа `dev` не попадает в production.
Для локальной разработки требуется uv; активация окружения вручную не нужна.
Полный набор команд описан в [руководстве разработчика](../development.md).

## Альтернативы

Сохранить requirements как второй источник зависимостей: требует поддерживать
дублирующиеся декларации и отдельную синхронизацию версий.

Заменить pip на `uv pip install` без project workflow: ускоряет установку,
но не подключает единый `pyproject.toml` и `uv.lock` для запуска и Docker.
