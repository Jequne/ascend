# Архитектурные решения

ADR (Architecture Decision Record) хранит контекст и причины решений, которые
сложно восстановить только по коду. ADR не заменяет обзор в
[`architecture.md`](../architecture.md): обзор описывает текущее устройство, ADR
объясняет, почему оно стало таким.

## Когда нужен ADR

- меняются границы компонентов или направление зависимостей;
- выбирается база, broker, framework, внешний provider или протокол;
- меняется модель безопасности, хранения данных или развертывания;
- принимается осознанный долгосрочный компромисс.

Исправление локального бага, небольшой рефакторинг и обратимо добавленная
настройка обычно ADR не требуют.

## Именование и статусы

Файлы именуются `NNNN-short-title.md`, номера не переиспользуются. Допустимые
статусы: `proposed`, `accepted`, `superseded`, `deprecated`, `rejected`.

Новый документ создается по [шаблону](template.md). Если решение заменено,
старый ADR остается в истории и получает ссылку на новый.
