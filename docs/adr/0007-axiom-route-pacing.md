# 0007. Очереди показателей и ограничение запросов по маршруту Axiom

- Статус: `accepted`
- Дата: `2026-09-29`
- Участники: разработчик Ascend

## Контекст

Общий интервал 100 мс ограничивал все HTTP-запросы Axiom, даже когда у агентов
были разные proxy-маршруты. При потоке новых пар запросы fees ранее полученных
токенов занимали ту же FIFO-очередь, что и первые запросы истории новых пар.
Несколько агентов одного прокси разделяют один выходной адрес, поэтому число
агентов само по себе не даёт безопасного увеличения темпа.

Публичную числовую квоту для используемых HTTP-endpoint Axiom подтвердить не
удалось. Нельзя гарантировать отсутствие `429` или блокировки IP только
локальным ограничителем; остаются внешние запросы и правила провайдера.

## Решение

Общий интервал стартов равен 100 мс, делённым на число независимых маршрутов,
но учитываются не более четырёх маршрутов. Для каждого маршрута отдельно
действуют интервал не менее 100 мс, предел восьми одновременных запросов,
cooldown по `Retry-After` и замедление после `429`. Маршрут определяется по
схеме, host и port прокси без учётных данных; все прямые агенты делят один
маршрут. Выбор агента выполняется после ожидания очереди. При заполнении
маршрутов запрос ждёт освобождения ёмкости, не удерживая общий слот.

Очередь разделена на первичную историю кошельков и поиск funder, проверку fees,
дополнительные изображения и ссылки. После двух проверок fees выполняется один
ожидающий первичный запрос. После десяти запросов данных допускается один запрос
дополнительных сведений. Внутри каждой группы сохраняется FIFO и все запросы
дожидаются обработки; приоритет не удаляет старые токены.

## Последствия

Несколько действительно независимых маршрутов повышают общую пропускную
способность без увеличения заданного темпа на одном маршруте. Новая пара
получает историю раньше накопившихся проверок fees. При одном маршруте общий
интервал остаётся прежним; предел одновременных запросов защищает его при
медленных ответах. Суммарный поток к Axiom при нескольких маршрутах возрастает,
поэтому `429` нужно наблюдать в диагностике и проверять работу на реальных
маршрутах. Если прокси с разными адресами подключения выводят трафик через
один внешний IP, локальный идентификатор маршрута этого не обнаружит.

Тесты проверяют общий и помаршрутный интервалы, объединение учётных данных
одного прокси, предел параллелизма, `429` и отсутствие голодания очередей.

## Альтернативы

Уменьшить единый интервал для всех агентов означало бы ускорить запросы и на
одном IP. Оставить одну FIFO-очередь сохраняло бы задержку первого запроса
новой пары во время всплеска проверок fees. Отбрасывание старых токенов
нарушило бы требование обработать каждое событие.
