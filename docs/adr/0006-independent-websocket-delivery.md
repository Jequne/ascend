# 0006. Независимая доставка WebSocket-событий клиентам

- Статус: `accepted`
- Дата: `2026-09-29`
- Участники: разработчик Ascend

## Контекст

Одна серверная задача читала очередь token feed и последовательно ожидала
`send_json` каждого подключённого клиента. Медленный или зависший получатель
останавливал отправку остальным, а в общей очереди накапливались базовые события
и уточнения уже открытых карточек. Увеличение частоты запросов к Axiom не решает
эту задержку и повышает риск ограничения IP.

## Решение

Для каждого клиентского соединения создаются отдельная FIFO-очередь на 64
сообщения и одна задача отправки. Общая рассылка только кладёт сообщение в
очереди без ожидания сети. Отправка внутри соединения сохраняет порядок событий.
При переполнении очереди соединение удаляется из активных сессий и закрывается
кодом 1013. После ошибки отправки соединение также удаляется и закрывается.
HTTP-пайплайн Axiom и общий ограничитель запросов остаются независимыми от
доставки клиентам.

## Последствия

Задержка одного соединения не задерживает остальные и не блокирует чтение
очереди token feed. Память на ожидающие сообщения ограничена числом соединений
и размером их очередей. Перегруженный клиент может пропустить события при
переподключении: протокол не хранит историю для повторной доставки.
Регрессионные тесты проверяют порядок сообщений, изоляцию медленного клиента
и закрытие при переполнении.

## Альтернативы

Параллельная отправка одного события всем клиентам с ожиданием `gather`
по-прежнему задерживает чтение следующего события из-за медленного клиента.
Независимая задача на каждое сообщение убирает ожидание, но не ограничивает
число задач и может нарушить порядок обновлений одной карточки.
